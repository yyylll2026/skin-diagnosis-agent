| 项 | 值 |
|----|----|
| Base URL | `http://127.0.0.1:8000` |
| API 前缀 | `/api/v1` |
| 交互式文档 | `GET /docs`（Swagger UI）· `GET /redoc` |

## 1. 通用约定

### 会话 ID

所有对话类接口都接受 `session_id`：

- **传 null / 不传** → 后端生成（格式 `s-<12位hex>`），并通过 SSE 的 `meta` 事件或
  JSON 响应的 `session_id` 字段回传；
- **传已有 ID** → 后端从元数据库（SQLite / PostgreSQL）读出最近 6 轮历史注入上下文，实现多轮对话。

前端应在首次响应后把 `session_id` 存下来，后续请求复用。

### 意图取值

| 值 | 含义 | 触发条件 |
|----|------|---------|
| `kb_qa` | 知识库问答 | 纯文本且命中皮肤相关关键词 |
| `image_diagnosis` | 图片诊断 | 请求中包含有效图片 |
| `chitchat` | 闲聊 | 寒暄模板命中或输入为空 |

### 降级语义

后端遵循「**能答就答，答不了说清楚**」的原则，不会因为单一依赖故障而整体失败：

| 故障 | 行为 |
|------|------|
| Ollama 不可达 | 返回 503 `ollama_unavailable`，消息含启动指引 |
| 视觉模型输出无法解析 | 降级为纯文本回答，`errors` 中说明原因 |
| 知识库为空 / 未命中 | 正常回答，提示「现有资料未涵盖」，`sources` 为空数组 |
| 检索服务异常 | 跳过检索直接生成，`errors` 记录原因 |
| 图片格式非法 | 返回 400 `image_invalid`，不消耗模型推理 |

## 2. 对话与诊断

### 2.1 POST /agent/chat

**智能体统一入口**（纯文本 / 图片 / 图文混合）。三个对话入口最终都汇流到同一张
LangGraph 状态图，因此行为完全一致。

**Request** — `application/json`

| 字段 | 类型 | 必填 | 默认 | 说明 |
|------|------|:----:|------|------|
| `session_id` | string \| null | ✗ | null | 为空则新建 |
| `message` | string | ✗ | `""` | 用户文本，≤2000 字 |
| `image_base64` | string \| null | ✗ | null | 图片 base64；可带 `data:image/jpeg;base64,` 前缀（后端会自动剥掉） |
| `image_mime` | string | ✗ | `image/jpeg` | 图片 MIME |
| `use_knowledge` | boolean | ✗ | `true` | 是否启用知识库检索增强 |
| `stream` | boolean | ✗ | `true` | true → SSE；false → 一次性 JSON |

> **可选字段显式传 `null` 是合法的**（等价于「不传」）。
> 例如纯文本提问时写成 `"image_mime": null` 会被归一化为 `"image/jpeg"`，
> `"message": null` 归一化为 `""`，`"use_knowledge": null` 归一化为 `true`。
> 因此前端**不需要**为了避开校验而手工裁剪字段——多传 null 不会 400。
>
> 之所以专门说明这一点：默认值只在字段**缺失**时生效，显式 `null` 在严格校验下
> 会被判为类型错误。而 JS 客户端用 `obj.field ?? null` 构造请求体是最自然的写法，
> 接口必须容忍这种差异，否则前后端会在「字段该不该裁剪」上产生无谓耦合。

```bash
curl -X POST http://127.0.0.1:8000/api/v1/agent/chat \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": null,
    "message": "脸部反复红斑伴脱屑两个月了，怎么护理？",
    "use_knowledge": true,
    "stream": false
  }'
```

**Response（`stream: false`）**

```json

  "vision": null,
  "sources": [
    {
      "doc_id": "8c2f1a9b4e7d0356",
      "title": "01-常见皮肤疾病概述",
      "source": "01-常见皮肤疾病概述.md",
      "category": "皮肤疾病",
      "snippet": "湿疹是一组以红斑、丘疹、水疱、渗出、结痂和剧烈瘙痒为特征的炎症性皮肤病……",
      "score": 0.7312,
```

### 2.2 POST /chat/qa

**知识库问答**（纯文本）。与 `/agent/chat` 的唯一区别是**强制忽略图片字段**，
保证走「检索 → 生成」链路。保留独立接口的用途：前端「文字问答」入口的契约更清晰，
也便于对 RAG 效果做单变量测试。

**Request / Response** — 同 `/agent/chat`，`image_base64` 会被忽略。

```bash
curl -X POST http://127.0.0.1:8000/api/v1/chat/qa \
  -H "Content-Type: application/json" \
  -d '{"message": "皮肤溃疡超过多久不愈合需要就医？", "stream": false}'
```

### 2.3 POST /diagnosis/image

**图片识别与诊断**。用 multipart 上传（适合大文件与浏览器原生表单），
返回一次性 JSON，便于前端渲染「诊断卡片」而不是流式气泡。

**Request** — `multipart/form-data`

| 字段 | 类型 | 必填 | 默认 | 说明 |
|------|------|:----:|------|------|
| `file` | file | ✓ | — | 皮肤照片，`Content-Type` 必须为 `image/*` |
| `session_id` | string | ✗ | 自动生成 | 会话 ID |
| `note` | string | ✗ | `""` | 用户补充描述 |
| `use_knowledge` | boolean | ✗ | `true` | 是否检索知识库补充依据 |

```bash
curl -X POST http://127.0.0.1:8000/api/v1/diagnosis/image \
  -F "file=@./lesion.jpg;type=image/jpeg" \
```

## 3. SSE 事件协议

**为什么用 fetch 而不是 EventSource**：需要 POST + JSON body（图片 base64），
原生 `EventSource` 只支持 GET。前端用 `fetch` + `body.getReader()` 手工解析。

**报文格式**：`event: <类型>\n data: <JSON>\n\n`。
服务端每 15 秒发送心跳，防止中间层因空闲断开连接。

| 事件 | 载荷 | 说明 |
|------|------|------|
| `meta` | `{session_id, has_image, use_knowledge, nodes}` | 请求受理。`route` 完成后会再发一次，带 `intent` |
| `node` | `{node, label, status, elapsed_ms?}` | `status` = `running` \| `done` |
| `vision` | `VisionDiagnosis`（见 [6.2](#62-visiondiagnosis)） | 视觉分析完成 |
| `sources` | `RetrievedChunk[]` | 检索完成 |
| `token` | `{text}` | 生成的增量文本 |
| `answer` | `{text}` | **兜底整段答案**（仅当 token 流为空时下发） |
| `done` | `{answer, safety, elapsed_ms, intent, errors}` | 全流程结束 |
| `error` | `{code, message, detail}` | 异常，前端应终止「生成中」状态 |

**节点中文标签**（`node` / `label` 对应关系）

| node | label |
|------|-------|
| `preprocess` | 预处理输入 |
| `route` | 意图识别 |
| `vision_analyze` | 图像分析 |
| `build_query` | 构建检索意图 |
| `retrieve` | 检索知识库 |
| `generate` | 生成回答 |
| `safety_review` | 安全审查 |

**完整报文示例**

```
event: meta
data: {"type":"meta","session_id":"s-3f9a2b","has_image":true,"use_knowledge":true,"nodes":["preprocess","route","vision_analyze","build_query","retrieve","generate","safety_review"]}

event: node
data: {"type":"node","node":"preprocess","label":"预处理输入","status":"running"}

event: node
data: {"type":"node","node":"preprocess","label":"预处理输入","status":"done","elapsed_ms":182.4}

event: meta
data: {"type":"meta","intent":"image_diagnosis"}

event: node
data: {"type":"node","node":"vision_analyze","label":"图像分析","status":"done","elapsed_ms":14320.6}

event: vision
data: {"type":"vision","data":{"summary":"……","risk_level":"medium","hypotheses":[…]}}

event: sources
data: {"type":"sources","data":[{"doc_id":"8c2f1a9b","title":"……","score":0.73}]}

event: token
data: {"type":"token","text":"## 观察到"}

event: token
data: {"type":"token","text":"的表现\n- 左侧面颊"}

event: done
data: {"type":"done","answer":"……","safety":{"risk_level":"medium","must_see_doctor":false},"elapsed_ms":31680,"intent":"image_diagnosis","errors":[]}
```

## 4. 知识库管理

### 4.1 POST /kb/documents

上传文档入库。同一份文件（内容 SHA1 相同）重复上传会**覆盖**旧版本，不会产生重复向量。

**Request** — `multipart/form-data`

| 字段 | 类型 | 必填 | 默认 | 说明 |
|------|------|:----:|------|------|
| `file` | file | ✓ | — | 支持 `.pdf` `.docx` `.md` `.markdown` `.txt` `.html` `.htm` |
| `category` | string | ✗ | `其他` | 建议取值：`皮肤疾病` / `用药指南` / `护理建议` / `其他` |
| `title` | string | ✗ | 文件名 | 自定义标题 |

**Response `200`**

```json
{
  "doc_id": "8c2f1a9b4e7d0356",
  "title": "01-常见皮肤疾病概述",
  "source": "01-常见皮肤疾病概述.md",
  "category": "皮肤疾病",
  "chunk_count": 42,
  "elapsed_ms": 3120,
  "message": "已入库 42 个文本块"
}
```

**错误**：`415` 格式不支持 ｜ `422` 解析失败（如纯扫描版 PDF 无文字层）

```bash
curl -X POST http://127.0.0.1:8000/api/v1/kb/documents \
  -F "file=@./皮肤科手册.pdf" -F "category=皮肤疾病"
```

### 4.2 GET /kb/documents

列出已入库文档（按入库时间倒序）。

```json
[
  {
    "doc_id": "8c2f1a9b4e7d0356",
    "title": "01-常见皮肤疾病概述",
    "source": "01-常见皮肤疾病概述.md",
    "category": "皮肤疾病",
    "chunk_count": 42,
    "size_bytes": 12480,
    "created_at": "2026-09-10T15:02:11"
  }
]
```

### 4.3 DELETE /kb/documents/{doc_id}

删除文档：清向量块 + 删登记 + 删上传文件。
**人工投放到 `data/docs/` 的原始语料不会被删除**（只从索引移除）。

```json
{ "deleted": true, "doc_id": "8c2f1a9b4e7d0356", "file_removed": true }
```

**错误**：`404` 文档不存在

### 4.4 POST /kb/search

**检索调试接口**：直接调用混合检索链路，不经过 LLM。调分块与权重时用它最快。

**Request**

```json
{ "query": "面部红斑伴鳞屑如何鉴别", "top_k": 5, "category": null }
```

| 字段 | 类型 | 必填 | 约束 |
|------|------|:----:|------|
| `query` | string | ✓ | 1~500 字 |
| `top_k` | int | ✗ | 1~20，默认 5 |
| `category` | string \| null | ✗ | null = 全库 |

**Response**

```json
{
  "query": "面部红斑伴鳞屑如何鉴别",
  "count": 3,
  "elapsed_ms": 128,
  "results": [
    {
      "doc_id": "8c2f1a9b4e7d0356",
      "title": "01-常见皮肤疾病概述",
      "source": "01-常见皮肤疾病概述.md",
      "category": "皮肤疾病",
      "snippet": "亚急性期：渗出减少，出现鳞屑与轻度浸润……",
      "score": 0.6841,
      "chunk_index": 5,
      "page": null,
      "retriever": "hybrid"
    }
  ]
}
```

**错误**：`400` `query` 为空

### 4.5 POST /kb/reindex

清空向量库并从 `data/docs/` 全量重建。**更换 embedding 模型后必须执行**。

```json
{
  "reindexed": 4,
  "total_chunks": 168,
  "elapsed_ms": 15420,
  "details": [ /* IngestResult[] */ ]
}
```

### 4.6 POST /kb/reset

清空向量库与文档登记表（不可撤销）。

**Query**：`confirm=true`（必须显式传，否则 `400`）

```json
{ "reset": true }
```

### 4.7 GET /kb/eval/starter

返回一份可直接编辑的**检索评测标注模板**，用于给前端预填。

标注的粒度是**文档**（`doc_id` / 标题 / 原始文件名任一匹配即算命中），不是 chunk——
换 embedding 或改分块参数重建索引后 chunk_id 会全变，标注绑在文档上才能长期复用。
模板里的 `relevant` 是示例文档标题，**需要替换成自己知识库里的真实标题或文件名**。

```json
{
  "name": "示例标注集",
  "description": "把 relevant 换成你知识库里的真实文档标题或文件名后再运行。",
  "cases": [
    {
      "query": "面部红斑伴鳞屑如何鉴别",
      "relevant": ["银屑病科普", "脂溢性皮炎护理"],
      "category": "鉴别诊断",
      "note": "示例标注，请替换"
    }
  ]
}
```

### 4.8 POST /kb/eval/run

在提交的标注集上量化混合检索效果。**只走检索链路，不调用生成模型**——
几十条样本几秒就能跑完，可以频繁回归；指标掉了能靠逐条明细直接定位到具体样本。

请求体：

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `cases` | `EvalCase[]` | 必填 | 标注样本，1~200 条 |
| `top_k` | int | `5` | 取前 K 条参与指标计算（1~20） |
| `category` | string \| null | `null` | 限定在某分类内检索，`null` 表示全库 |
| `use_rerank` | bool \| null | `null` | 覆盖重排开关；`null` 表示跟随服务端配置 |

`EvalCase.relevant` 中每个标签**至少 2 个字符**——单字标签会让子串判定几乎全命中，
指标虚高到没有意义，因此在 schema 层直接拒绝（返回 `422`）。

```json
{
  "cases": [
    { "query": "面部红斑伴鳞屑如何鉴别", "relevant": ["银屑病科普"], "category": "鉴别诊断" },
    { "query": "接触性皮炎怎么护理", "relevant": ["接触性皮炎护理"], "category": "护理" }
  ],
  "top_k": 5,
  "category": null,
  "use_rerank": false
}
```

响应：汇总指标 + 按归类分组 + 逐条明细。

```json
{
  "metrics": {
    "case_count": 2,
    "k": 5,
    "hit_rate": 1.0,
    "mrr": 0.75,
    "recall_at_k": 1.0,
    "precision_at_k": 0.2
  },
  "by_category": [
    { "category": "鉴别诊断", "case_count": 1, "k": 5, "hit_rate": 1.0, "mrr": 1.0, "recall_at_k": 1.0, "precision_at_k": 0.2 }
  ],
  "cases": [
    {
      "query": "面部红斑伴鳞屑如何鉴别",
      "relevant": ["银屑病科普"],
      "category": "鉴别诊断",
      "hit": true,
      "first_hit_rank": 1,
      "matched": ["银屑病科普"],

      "recall": 1.0,
      "precision": 0.5,
      "reciprocal_rank": 1.0,
      "elapsed_ms": 312,
      "note": ""
    }
  ],
  "top_k": 5,
  "category": null,
  "use_rerank": false,
  "elapsed_ms": 640,
  "notes": ""
}
```

**指标含义**

| 指标 | 含义 |
|------|------|
| `hit_rate` | 命中率：前 K 条里至少出现一个期望文档的样本占比 |
| `mrr` | 平均倒数排名：首个正确结果名次取倒数后求均值，越靠前越高 |
| `recall_at_k` | 召回率：期望文档被找出来的平均比例（该给模型看的资料有没有被捞到） |
| `precision_at_k` | 准确率：召回结果中相关文档的平均占比 |

**错误**：`422` 标注集为空、超过 200 条，或 `relevant` 出现单字标签。

### 5.7 后台图像分析任务

**`POST /analysis-tasks`** 返回 HTTP `202` 与任务 ID。图片仅在服务进程内存中处理，不写入任务表；任务状态及完成结果持久化到元数据库（SQLite / PostgreSQL）。

```json
{
  "session_id": null,
  "message": "左侧面颊红斑，持续三天",
  "image_base64": "iVBORw0KGgo...",
  "image_mime": "image/jpeg",
  "use_knowledge": true
}
```

响应示例：

```json
{
  "task_id": "t-a1b2c3d4e5f60718",
  "session_id": "s-3f9a2b1c4d5e",
  "status": "queued",
  "progress": 0,
  "current_step": "排队中",
  "result": null,
  "error": "",
  "retry_available": false,
  "attempt_count": 1,
  "created_at": "2026-10-03T10:00:00",
  "updated_at": "2026-10-03T10:00:00",
  "started_at": "",
  "finished_at": ""
}
```

| 方法 | 路径 | 行为 |
|------|------|------|
| GET | `/analysis-tasks?limit=50&offset=0` | 当前用户的任务列表（最多 100 条/页） |
| GET | `/analysis-tasks/{task_id}` | 查询状态、当前节点进度与最终结果 |
| POST | `/analysis-tasks/{task_id}/cancel` | 取消排队或运行中的任务 |
| POST | `/analysis-tasks/{task_id}/retry` | 失败/取消后重试；仅当原图仍在当前进程的短时内存缓存中可用 |

状态为 `queued` / `running` / `succeeded` / `failed` / `cancelled`。成功时 `result` 包含 `answer`、`vision`、`sources`、`safety`、`clarify`、`elapsed_ms` 等结果；任务只能由所属用户访问（管理员也不能代看客户任务）。

- 服务重启后，未完成任务标记为 `failed`，提示用户重新上传；图片不会从数据库恢复。
- 当前任务调度器为单进程内存队列，默认并发 1、最多额外排队 2 项；失败重试原图最多缓存 2 项、默认 15 分钟。多 worker/多副本部署应换用 Redis/Celery 等共享任务队列。
- 删除会话或账号时会清除关联任务；删除账号同时清理该账号的个人健康记录。

### 5.9 GET /health-records/trends

把当前用户的健康记录聚合成病程趋势，供前端画图。**只做「换个角度呈现用户自己填的记录」，不引入任何医学判断**。

| Query | 类型 | 默认 | 说明 |
|-------|------|------|------|
| `days` | int | `90` | 统计窗口天数，取值 7~730 |

响应包含三组序列：

- `daily` — 按日序列，从窗口内最早一条记录起**连续补零**（没记录的日子 `count=0`、分数为 `null`），前端据此画出连续时间轴，避免空档被压缩造成「一直在发作」的错觉；
- `body_sites` — 按部位聚合（次数、最近一次日期、最重程度、平均分、占比），按次数降序、同次数按最近时间排序；
- `severities` — 按自述程度分布，顺序固定（由重到轻）。

```json
{
  "window_days": 90,
  "range_start": "2026-07-01",
  "range_end": "2026-10-01",
  "total_records": 6,
  "total_records_all": 9,
  "active_days": 4,
  "body_site_count": 2,
  "daily": [
    { "recorded_on": "2026-09-28", "count": 1, "max_score": 1.0, "avg_score": 1.0, "worst_severity": "mild" },
    { "recorded_on": "2026-09-29", "count": 0, "max_score": null, "avg_score": null, "worst_severity": null }
  ],
  "body_sites": [
    { "body_site": "左侧面颊", "count": 4, "last_recorded_on": "2026-10-01", "worst_severity": "moderate", "avg_score": 1.5, "share": 0.667 }
  ],
  "severities": [
    { "severity": "unknown", "count": 0, "share": 0.0 },
    { "severity": "mild", "count": 4, "share": 0.667 },
```

### 6.1 RetrievedChunk

| 字段 | 类型 | 说明 |
|------|------|------|

## 7. 错误码

统一错误响应体：

```json
{ "code": "image_invalid", "message": "图片体积 12.3MB 超过上限 8.0MB，请压缩后重试", "detail": null }
```

| HTTP | `code` | 触发场景 | 前端建议处理 |
|:----:|--------|---------|------------|
| 400 | `image_invalid` | 图片格式非法、体积超限、已损坏 | 提示重新选择图片 |
| 400 | `validation_error` | 请求参数校验失败 | 提示具体字段 |
| 400 | `document_parse_failed` | 文档解析失败（如扫描版 PDF） | 提示换格式或提供文字版 |
| 404 | — | 文档 / 资源不存在 | 刷新列表 |
| 415 | — | 文档格式不支持 | 提示支持的格式 |
| 422 | — | 文档内容无法解析 | 提示文件内容问题 |
| 502 | `model_output_invalid` | 模型输出无法解析为约定结构 | 提示重试或更换更大模型 |
| 503 | `ollama_unavailable` | Ollama 不可达 | 提示 `ollama serve` |
| 503 | `embedding_failed` | 向量化失败（如 embedding 模型未拉取） | 提示 `ollama pull bge-m3` |
| 500 | `internal_error` | 未预期异常（细节仅进日志） | 提示查看后端日志 |

> **实现约定**：`message` 面向用户、可直接展示；`detail` 面向开发，生产环境可能为 null。

## 8. 前端接入示例

### 8.1 SSE 流式对话（fetch + ReadableStream）

```js
export async function streamAgentChat(payload, handlers = {}) {
  const {
    onMeta, onNode, onVision, onSources, onToken, onDone, onError,
  } = handlers;

  const controller = new AbortController();
  const response = await fetch('/api/v1/agent/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ ...payload, stream: true }),
    signal: controller.signal,
  });

  // 非 200：把响应体读出来当作错误详情，而不是抛一个空异常
  if (!response.ok) {
    const text = await response.text();
    let message = `请求失败（HTTP ${response.status}）`;
    try { message = JSON.parse(text).message || message; } catch { message = text || message; }
    onError?.({ code: 'http_error', message });
    return controller;
  }

  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;

    // 流式解码 + 跨 chunk 累积：多字节中文可能被切在两个 chunk 之间
    buffer += decoder.decode(value, { stream: true }).replace(/\r\n/g, '\n');

    // 按空行切分事件块；最后一段可能不完整，留在 buffer 里等下一个 chunk
    const blocks = buffer.split('\n\n');
    buffer = blocks.pop() ?? '';

    for (const block of blocks) {
      let eventName = 'message';
      let dataLine = '';
      for (const line of block.split('\n')) {
        if (line.startsWith('event:')) eventName = line.slice(6).trim();
        else if (line.startsWith('data:')) dataLine += line.slice(5).trim();
      }
      if (!dataLine || dataLine === '[DONE]') continue;

      let payloadObj;
      try { payloadObj = JSON.parse(dataLine); } catch { continue; }

      // 事件名以报文里的 type 为准，兼容服务端省略 event: 行的情况
      const type = payloadObj.type || eventName;
      if (type === 'meta') onMeta?.(payloadObj);
      else if (type === 'node') onNode?.(payloadObj);
      else if (type === 'vision') onVision?.(payloadObj.data);
      else if (type === 'sources') onSources?.(payloadObj.data);
      else if (type === 'token') onToken?.(payloadObj.text);
      else if (type === 'answer') onToken?.(payloadObj.text);
      else if (type === 'done') onDone?.(payloadObj);
      else if (type === 'error') onError?.(payloadObj);
    }
  }

  return controller; // 调用方可用 controller.abort() 实现「停止生成」
}
```

### 8.2 图片转 base64

```js
export function fileToBase64Payload(file) {
  return new Promise((resolve, reject) => {
    const reader = new FileReader();
    reader.onerror = () => reject(new Error('图片读取失败'));
    reader.onload = () => {
      const result = String(reader.result);
      const comma = result.indexOf(',');
      resolve({
        // 只传纯 base64；mime 单独传（后端也兼容带前缀的写法）
        image_base64: comma >= 0 ? result.slice(comma + 1) : result,
        image_mime: file.type || 'image/jpeg',
      });
    };
    reader.readAsDataURL(file);
  });
}
```

### 8.3 前端预校验（减少无谓的往返）

```js
const ALLOWED = ['image/jpeg', 'image/png', 'image/webp'];
const MAX_MB = 8;

export function validateImage(file) {
  if (!ALLOWED.includes(file.type)) return '仅支持 JPG / PNG / WEBP 格式';
  if (file.size > MAX_MB * 1024 * 1024) {
    return `图片体积 ${(file.size / 1024 / 1024).toFixed(1)}MB 超过上限 ${MAX_MB}MB`;
  }
  return null; // 通过
}
```

> 前端预校验只是体验优化，**后端仍会完整校验**（体积、格式、可解码性、亮度、分辨率）——
> 前端校验可以被绕过，安全边界必须在服务端。
