## 四、已知坑位（提前告知）

| 风险 | 说明 | 应对 |
|------|------|------|
| 构建时拉不到基础镜像 | 平台构建环境访问 Docker Hub 受限 | 若报错，把 `Dockerfile` 两个 `FROM` 换成平台可达的镜像源（本机实测可用：`docker.1ms.run/library/...`） |
| 端口不通 | 平台占用 8080，必须用 7860 | `ms_deploy.json` 已固定 7860，不要改 |
| 重启后知识库变空 | 数据未落持久化目录 | `SKIN_DATA_ROOT=/mnt/workspace/data` 已写死在镜像里 |
| 图片诊断很慢 | 2 核 CPU 跑视觉模型是固有代价 | 默认已降级为 `qwen2.5vl:3b` + 图片长边 1024px，预计 30 秒~2 分钟/张 |
| 免费配额有时限 | 平台会回收长时间无访问的资源 | 定位是演示与自用，不要当生产依赖 |

## 五、上线前的边界确认

- **隐私边界变了**：本项目原始定位是本地推理、数据不出内网。部署到公网后，
  用户上传的皮肤照片会离开本机。涉及真实患者数据时请勿使用公网部署。
- **合规边界**：本系统声明「不构成医疗诊断」。公网开放面向不特定人群，
  免责声明与强制就医提示是必要条件，但不等于满足医疗器械监管要求。
- **鉴权已开启**（`auth_enabled: true`），但仍无限流；公网暴露时任何人都能
  消耗你的推理资源，建议后续加一层网关限流或访问来源限制。
